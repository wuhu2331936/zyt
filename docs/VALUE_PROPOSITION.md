# 智药通 VS 通用大模型助手 —— 独立价值论证

> 回应评委意见：「感觉这些功能豆包这类软件也能做，请论证你们软件的独立价值」
>
> 本文从**功能边界、技术实现、实测对比、目标人群适配**四个维度论证：
> 智药通不是"套壳大模型"，而是一个**以用药安全为唯一目标的垂直工具**，
> 与通用助手是"专用计算器"与"全能聊天机器人"的关系。

---

## 一、核心论点：通用助手回答"什么都问"，智药通只答"用药"，但答得更对

豆包等通用助手定位是**开放式对话**，用药只是它无数话题之一；
智药通把全部工程投入压在**一条链路**上：拍照识药 → 查说明书 → 核对相互作用 → 老年人可用的呈现。

专用化的代价是"功能窄"，换来的是四项通用助手**没有做、也不会为个别场景做**的工程：

| # | 能力 | 智药通 | 通用大模型助手（豆包等） |
|---|------|--------|--------------------------|
| 1 | **药品说明书 RAG 检索** | 内置 ChromaDB 向量库，对 NMPA 说明书文本建立索引；回答前先检索原文，把说明书片段注入 Prompt，**答案可溯源到说明书** | 直接生成。说明书是否被检索过不可知，答案无出处 |
| 2 | **药物相互作用核查引擎** | 独立规则引擎（DeepSeek 结构化输出 + 程序校验双保险），逐对药物核查禁忌组合，输出风险等级 | 只能靠模型"记忆"，无核查步骤；多药同问时容易遗漏或含糊 |
| 3 | **两阶段视觉识药管线** | qwen-vl 先"认药"（药盒文字 OCR+匹配），DeepSeek 再"解释"（面向老人重写）。识别与解释解耦，识别错误不污染安全建议 | 一阶段直出，认错药后整段建议跟着错，用户无从发现 |
| 4 | **防幻觉约束** | 检索不到的药名 → 明确回答"未收录，请咨询药师"，**拒绝编造**；演示模式下预置答案+明确标注 | 通用助手倾向"尽力回答"，冷门药/复方药存在编造成分名、剂量的风险 |

## 二、四个"豆包做不到/不会做"的场景实录

### 场景 1：老人拍一张药盒，问"这个和我的降压药能一起吃吗"

- **豆包**：需要老人先打字描述药名（老人未必会写"苯磺酸氨氯地平"），再描述问题；一次对话只能覆盖一问，相互作用依赖模型记忆。
- **智药通**：拍照即识（无需打字）→ 自动调相互作用引擎核查 → 大字号红/黄/绿分级结论 → 语音播报。**从拍照到结论，全程 ≤3 次点击、0 次打字。**

### 场景 2：老人问"缬沙坦氢氯噻嗪片"这类复方药

- **通用助手**：复方药成分组合多，模型易把"缬沙坦"和"氢氯噻嗪"的注意事项混着说，甚至张冠李戴。
- **智药通**：说明书 RAG 检索不到时**直接说"未收录"**，提示咨询药师或社区医生——宁可少答，不可错答。

### 场景 3：老人听不清/看不清

- **通用助手**：默认 UI 为通用人群设计，字号、按钮密度、语音交互均为聊天流式，老人操作负担重。
- **智药通**：全程大字号（≥18sp 等效）、按住说话（免打字）、Edge-TTS 中文女声慢速播报、界面无广告无弹窗。

### 场景 4：断网/弱网（老年机常见）

- **通用助手**：完全依赖云端对话。
- **智药通**：用药提醒（核心兜底功能）本地存储本地触发，不依赖网络；无 API Key 时自动进入演示模式，流程可走通。

## 三、技术独立性的具体证据（非套壳）

| 工程模块 | 自研内容 | 大模型承担的角色 |
|---|---|---|
| `rag/` | ChromaDB 向量库构建、说明书切分与索引、检索注入 | 仅做最终措辞改写 |
| `interaction.py` | 相互作用规则核查引擎：DeepSeek 只负责结构化抽取药名，**风险判定是程序逻辑**，可单测可复现 | 结构化输出 |
| 两阶段视觉管线 | 识别与解释解耦，两阶段独立提示词、独立校验 | 各阶段一次调用 |
| `/api/voice/asr` | 自建录音上传 → 百炼 Paraformer 服务端转写链路（因国内安卓浏览器 Web Speech 走 Google 被墙，纯浏览器方案不可用——这是通用助手无需处理的工程问题） | 无 |
| 提醒引擎 | 本地定时、药物清单管理、逾期判定 | 无 |

一句话：**大模型只占链路的"语言"两端，中间的安全判定、检索、提醒、交互全部是自研工程**——
这正是"AI 应用"区别于"AI 套壳"的评判标准。

## 五、结论

通用助手是"什么都懂一点的聊天对象"，智药通是"只懂吃药、但把吃药这件事做安全的工具"：

1. **价值定位不同**：垂直安全工具 vs 通用对话产品；
2. **技术构成不同**：RAG + 规则引擎 + 两阶段视觉 + 本地提醒，大模型仅承担语言两端；
3. **可靠性标准不同**：智药通以"检索不到就拒绝回答"为安全底线，通用助手以"尽量回答"为体验目标——在用药场景，这两种取向的差距就是医疗风险；
4. **目标人群适配不同**：免打字、大字号、语音播报、本地提醒，均为老年人专门设计。
