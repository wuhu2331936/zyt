## 一、项目详情及使用方式

### 1.1 项目定位

智药通是一款面向老年人及照护者的**AI 用药安全助手**，提供**原生 Android App + H5/PWA 双端交付**：手机安装 APK 即是全屏原生应用；不便安装时浏览器打开在线地址同样可用。它解决三个老年人用药的高频痛点：

- **看不懂药盒**：字体小、说明书专业术语密集、药品名称相近难以分辨；
- **记不住风险**：同时服用多种药物时，相互作用和禁忌凭经验判断容易出错；
- **问诊不方便**：子女不在身边时，用药疑问无人可问。

### 1.2 核心功能

| 功能 | 说明 | 背后技术 |
|---|---|---|
| 拍照识药 | 对药盒实时拍摄或从相册上传，先由视觉模型读出盒面信息，再由大模型补全说明书级讲解（用法用量、禁忌、药师叮嘱） | 通义千问 VL（Qwen3-VL）+ DeepSeek 两阶段识别 |
| 用药安全分析 | 输入正在服用的多种药品，分析相互作用与风险等级（如「较严重」） | DeepSeek + ChromaDB RAG 检索增强 |
| 用药提醒 | 按医嘱设置提醒，到点弹窗 + 系统通知 + 语音播报，支持「吃了 / 撤销」 | 前端全局监听 + Notification + Web Speech |
| 语音问答 | 说话提问、语音回答，全程不用打字 | 前端录音（Web Audio）+ 阿里云百炼 Paraformer 转写 + DeepSeek + Edge-TTS |

### 1.3 使用方式

1. **安装 Android App（推荐）**：将作品包内 `智药通-v0.4.2.apk` 传到手机点开安装（允许"未知来源"即可），装完桌面出现图标，点开即全屏原生 App；详细步骤见作品包内《智药通APK安装说明.txt》；
2. **在线访问**：浏览器打开上方「在线体验」地址即可使用（已部署到腾讯云 CloudBase 云托管，7×24 小时可访问），支持"添加到主屏幕"作为 PWA 安装；
3. **本地部署**：仓库含 Dockerfile 与一键启动脚本，`pip install -r requirements.txt` 后 `uvicorn` 启动后端、`npm run dev` 启动前端；
4. **云端部署**：仓库含 Dockerfile 与 CloudBase 云托管配置，Git 推送后自动构建部署。

使用流程（以"多药同服风险分析"为例）：首页"我的用药清单"逐个添加正在服用的药品（支持拍照识药自动录入）→ 点击"检查药物相互作用" → 系统先从 30 条内置药品说明书向量库中检索相关段落，再由大模型给出风险等级、冲突说明与建议，全程语音可读。

## 二、项目亮点

1. **真实的适老化设计**：大字体、高对比度、语音优先的交互方式，界面文案经口语化改写（如"相互作用"改述为"一起吃会不会打架"），而非把通用界面简单放大。
2. **检索增强（RAG）约束幻觉**：不裸调大模型，先用 ChromaDB 从结构化药品说明书中检索相关段落，作为事实依据注入 Prompt，显著降低医学幻觉风险；检索不到时明确告知"建议咨询医师/药师"，而非编造答案。
3. **JSON Schema 结构化输出契约**：要求模型按固定 JSON Schema 返回（药品名、风险等级、建议列表），前端按契约渲染，保证输出稳定可解析。
4. **四级失败降级链**：RAG 检索失败 → 退化为纯模型知识；模型超时 → 重试一次；仍然失败 → 给出静态安全提示。任何单一外部依赖故障都不会导致白屏。
5. **双端交付 + 弱网兜底**：既提供原生 Android 安装包（Capacitor 打包，桌面图标、全屏体验），也保留可安装的轻量 PWA；针对云托管"最小实例 0"的冷启动特性，前端内置 45 秒超时 + 3 次递增自动重试 + 启动预热，空闲后的首次请求也能自动恢复，不白屏不报错。
6. **规范的软件工程**：Conventional Commits、65 次细粒度提交、版本化发布（v0.4.0→v0.4.2）、GitHub Actions CI（前端构建 + 后端 pytest 8 项测试）、MIT License、完整的需求/技术/部署/FAQ 文档。

## 三、AI 技术落地使用情况概述

### 3.1 产品内 AI 能力

- **通义千问 VL（DashScope API，qwen3-vl-plus）**：拍照识药第一阶段，读出药盒正面的药品名、规格、厂家、用法用量；对模糊照片返回"无法识别"而非猜测。
- **DeepSeek（OpenAI 兼容 API）**：识药第二阶段——基于第一阶段结果补全说明书级讲解（老年人注意事项、漏服处理、药师叮嘱）；同时承担用药问答、相互作用分析、风险总结。统一走服务端转发，Key 不落前端。
- **RAG 检索增强**：内置 30 条常见药品结构化说明书，bge-small-zh 中文向量模型 + ChromaDB 持久化检索，Top-4 段落注入 Prompt。
- **Edge-TTS**：中文语音合成回答，免费无 Key，适合老年用户"听"回答。

### 3.2 AI 辅助研发（AI 协同开发）

本项目由 AI 结对开发完成，过程留痕于仓库 `docs/ai-prompts/AI-COLLABORATION-LOG.md`，含 3 条完整可复现的 Prompt 链：

1. **架构设计链**：由需求推导出前后端分离 + RAG 的技术选型与目录结构；
2. **代码实现链**：分阶段生成后端服务/前端页面，并迭代修复跨平台兼容问题；
3. **测试与文档链**：AI 生成 pytest 测试用例、PWA 图标生成脚本与全套中文文档。

CI 中的 8 项 pytest 用例即由 AI 编写并在 AI 协作下定位修复了真实缺陷（如 RAG 可选依赖的导入守卫）。

## 四、项目中涉及的关键技术

- **后端**：Python FastAPI + Pydantic v2（请求/响应模型校验）、uvicorn、python-dotenv 环境配置；
- **前端**：Vue 3 组合式 API + Vite + Vant 组件库 + Pinia 状态管理 + Vue Router 懒加载，vite-plugin-pwa 实现 PWA；
- **原生打包**：Capacitor 6 将 Vue3 前端封装为签名 Android APK（Gradle 8.14 + AGP 8.2，release 签名构建），原生壳与云端 API 的跨源访问通过 CORS 白名单与请求重试链打通；
- **AI 集成**：DashScope SDK（Qwen-VL）、DeepSeek HTTP API、阿里云百炼 Paraformer（服务端语音识别）、Edge-TTS；
- **RAG**：ChromaDB 持久化向量库、BAAI/bge-small-zh 中文 Embedding、Top-K 检索 + Prompt 注入；
- **可靠性**：JSON Schema 输出约束、超时重试、四级降级链、可选依赖优雅降级（未安装 RAG 依赖时应用仍可启动）；
- **工程化**：GitHub Actions CI、Docker、pytest + httpx 异步测试、Conventional Commits。

## 七、是否基于其他项目优化

本项目为**从零开始的原创开发**，未基于任何已有项目二次开发，所有代码、文档、界面设计均可在仓库 Git 历史（65 次提交、6 个开发阶段）中追溯。

初赛提交后，针对评审反馈与真机实测做了以下**版本内迭代优化**（v0.4.1 → v0.4.2）：

| 优化项 | 内容 | 回应的问题 |
|---|---|---|
| 语音输入服务端化 | 前端 Web Audio 录音（16kHz WAV）上传，改由阿里云百炼 Paraformer 服务端转写，替代依赖 Google 服务器的浏览器 Web Speech API | 初赛版国产手机浏览器/微信内语音问答无法使用 |
| 原生 Android App | 接入 Capacitor 6 打出签名 release APK（3.2MB），桌面图标全屏运行，不再是网页 | 评语"不要做网页版" |
| 实时拍照恢复 | 识药拍照补 `capture="environment"` 属性，拆分「拍照识别 / 相册选择」双入口 | APK 内只能从相册选图、不能实时拍摄 |
| 跨源与冷启动容错 | CORS 白名单加入原生壳源（https://localhost），前端 45 秒超时 + 3 次递增重试 + 启动预热 | APK 内接口报"网络错误"、云托管空闲后首次请求 503 |
| 独立价值论证 | 新增《独立价值论证》（docs/VALUE_PROPOSITION.md）：功能边界/技术构成/防幻觉约束/适老化四维对比 | 评语"这些功能豆包也能做" |
