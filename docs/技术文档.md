## 1. 项目概述与创意定位

### 1.1 问题背景

我国 60 岁以上老年人中，约 75% 患有一种以上慢性病，人均同时服用 4~6 种药物。由此带来三类高频风险：

- **读不懂说明书**：药品说明书字体小、术语密集，老年人理解困难；
- **多药联用风险**：多种药物之间的相互作用（如华法林与阿司匹林联用增加出血风险）凭老人自身经验难以察觉；
- **漏服/错服**：记忆衰退导致服药时间混乱。

### 1.2 解决方案

「智药通」是一款面向老年人的 H5/PWA 应用，提供 4 个核心功能：

| 功能 | 说明 | AI 能力 |
|---|---|---|
| 拍照识药 | 拍摄药盒，自动识别药品名、规格、用法用量 | 通义千问 VL（多模态识图） |
| 相互作用检查 | 输入在服药品清单，输出 4 级风险提示 | ChromaDB 说明书向量检索 + DeepSeek 总结 |
| 语音服药提醒 | 大字号时间轴 + 语音播报提醒 | Edge-TTS（免费神经语音） |
| AI 用药问答 | 按住说话→转文字→大模型回答→语音播报 | Web Speech API + DeepSeek + Edge-TTS |

### 1.3 设计原则

- **适老化**：大字号（≥18px 基准）、高对比度、单任务单页面；
- **语音优先**：所有结果均可语音播报，降低读写负担；
- **安全兜底**：所有 AI 回答附带"请咨询医师或药师"免责提示；
- **离线可用**：PWA 缓存核心静态资源，弱网可打开应用壳。

               │ HTTPS / JSON（axios）
┌──────────────▼───────────────────────────────────┐

│  │  拍照识药   │  │ 相互作用检查 │  │ 问答+TTS   │  │
│  └─────┬──────┘  └─────┬──────┘  └─────┬──────┘  │
│        │               │               │          │
│  ┌─────▼───────────────▼───────────────▼───────┐ │
│  │            Services 服务层（异步）            │ │

└────────┼───────────────┼──────────────────────────┘
         │               │
   阿里云百炼        ChromaDB 持久化卷
   qwen-vl-plus   + BAAI/bge-small-zh 向量库
```

### 2.2 关键架构决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 前端框架 | Vue3 + Vite + Vant 4 | Vant 移动端组件成熟，适老化样式开箱可用 |
| 应用形态 | H5/PWA（非小程序） | 符合赛制要求；PWA 支持添加到桌面与离线缓存 |
| 后端框架 | FastAPI | 原生 async，适合并发调用大模型 API；自带 Swagger 便于评审核验 |
| 状态存储 | 前端 localStorage | 用药清单/提醒属于个人数据，本地存储零后端成本且保护隐私 |
| 识图模型 | qwen-vl-plus | 中文药盒识别准确率高，百炼平台提供免费额度 |
| 对话模型 | DeepSeek-chat | 性价比高，支持 JSON mode 保证结构化输出 |
| 语音合成 | Edge-TTS | 完全免费、无需 Key，中文神经语音自然度高 |
| 向量库 | ChromaDB + bge-small-zh | 轻量可本地运行，中文检索效果好，CPU 即可推理 |
| 部署 | Vercel + Render（Docker） | 免费层即可支撑演示；Docker 保证环境一致 |

### 2.3 代码分层

- **API 层**（`app/api/`）：路由与参数校验，不包含业务逻辑；
- **服务层**（`app/services/`）：全部大模型调用与 RAG 逻辑，均为 async 函数；
- **模型层**（`app/models/`）：Pydantic 模型定义请求/响应契约；
- **配置层**（`app/core/config.py`）：pydantic-settings 读取 `.env`，密钥不落代码。

## 3. 意图控制策略（Prompt 工程与上下文设计）

本项目的核心挑战是：**让大模型稳定输出"前端可直接渲染"的结构化结果**。我们采用五层意图控制策略。

### 3.1 策略一：角色设定 + 受众约束（系统提示词）

每次对话都注入角色系统提示词，并显式约束输出受众。以用药问答为例：

```
你是「智药通」的AI药师助手，服务对象是老年人。
规则：
1. 用通俗语言，避免专业术语；必须用到的术语要立即用生活化比喻解释
2. 回答控制在150字以内，分点说明
3. 涉及处方药调整、剂量变化时，必须提醒"请咨询医师或药师"
4. 不确定时明确说"我不确定"，绝不编造
5. 不推荐具体药品品牌，只解释通用名药物知识
```

**意图控制要点**：第 4 条"绝不编造"是医疗场景的硬约束；第 3 条把安全责任显式交还专业人员。

### 3.2 策略二：结构化输出契约（JSON Schema 约束）

识药与相互作用检查接口要求模型返回严格 JSON。三层保障：

1. **API 层**：DeepSeek 开启 `response_format={"type": "json_object"}`，VL 模型在提示词中给出完整 JSON Schema 并要求"不要任何多余文字、不要 markdown 代码块"；
2. **解析层**：`_safe_json_parse` 容错函数——自动剥离 ```json 围栏、正则提取首个 `{...}` 块、失败时返回兜底结构（前端不崩溃）；
3. **校验层**：Pydantic 模型二次校验字段类型，非法字段自动丢弃。

### 3.3 策略三：检索增强注入（RAG 上下文构造）

相互作用检查不依赖模型记忆，而是先检索本地说明书向量库，将 Top-4 相关片段拼入提示词：

```
以下是检索到的药品说明书片段：
【片段1】华法林钠片：…与阿司匹林等抗血小板药合用可增加出血风险…
【片段2】阿司匹林肠溶片：…与抗凝药合用…
请仅依据以上片段 + 你的药学知识，按 JSON Schema 输出风险分析。
若片段与问题无关，请忽略片段。
```

**意图控制要点**：显式告知模型"片段无关时忽略"，避免检索噪声污染回答。

### 3.4 策略四：温度与 token 的分场景调参

| 场景 | temperature | max_tokens | 理由 |
|---|---|---|---|
| 识药信息抽取 | 0.1 | 800 | 事实抽取，宁低勿飘 |
| 相互作用分析 | 0.1 | 1000 | 风险等级判定需稳定 |
| 用药问答 | 0.5 | 500 | 保留一定语言自然度 |

### 3.5 策略五：上下文长度与多轮管理

- 语音问答保留最近 6 轮对话作为上下文，超出即裁剪最旧轮次，防止 token 超限与话题漂移；
- 每轮仅注入"药品清单摘要"（名称+规格），不注入完整说明书，控制上下文体积；
- TTS 播报文本在服务端先做"去 markdown 符号"清洗（去 `*`、`#`、表格符），避免语音朗读出符号噪音。

### 3.6 失败降级链

```
VL 识图失败 → 返回"无法识别，请正对药盒拍摄"提示，前端引导手动录入
RAG 向量库缺失 → 自动降级为 DeepSeek 内置知识分析（接口仍可用）
DeepSeek JSON 解析失败 → 兜底空结构 + 友好文案，HTTP 仍为 200
TTS 生成失败 → 前端回退 Web Speech API 浏览器本地合成
```

## 4. AI 模型集成细节

### 4.1 通义千问 VL（拍照识药）

- 调用方式：OpenAI 兼容模式访问百炼端点，图片转 base64 data URL 传入 `image_url`；
- 提示词要求返回字段：`name`（通用名）、`brand`、`specification`、`indication`、`dosage`、`frequency`、`precautions`、`confidence`；
- 置信度低于阈值时，前端提示"请手动确认"。

### 4.2 DeepSeek（对话与风险分析）

- 统一封装 `_complete_json` 通用方法：system 角色注入 + JSON mode + 安全解析；
- 用药问答另封装流式接口预留（阶段 6 后可升级打字机效果）。

### 4.3 Edge-TTS（语音合成）

- `edge-tts` 库异步生成 mp3，直接以 `Response(content=audio, media_type="audio/mpeg")` 流式返回；
- 提供 5 种中文音色（晓晓/云希/云扬/晓伊/晓梦），默认 `zh-CN-XiaoxiaoNeural`（老年用户实测接受度最高）；
- 支持语速参数（默认 `+0%`，可调 `+10%` 适配听力衰退用户）。

### 4.4 语音识别（前端方案）

- 主方案：Web Speech API（Chrome/Edge 免费内置）；
- 备选：科大讯飞 WS 接口（付费，网络环境更好时启用）——架构上前端封装 `audio.js` 适配器，可无痛切换。

## 5. RAG 检索增强：数据、构建与效果

### 5.1 数据来源

- **种子数据**：`backend/scripts/data/medicines.json`，收录 30 种老年高频用药（降压/降糖/抗凝/止痛/中成药），每条含通用名、规格、用法用量、相互作用、禁忌、不良反应；
- **扩展来源**（可复现路径）：国家药监局公开说明书、药智数据、 Drugs.com。构建脚本支持从 JSON 批量入库，也预留 PDF 说明书解析入口（pypdf）。

### 5.2 构建流程

```
medicines.json
   │ 1. 读取并清洗（去重、字段校验）
   ▼
按"药品名+相互作用"两条粒度切分文本块
   │ 2. BAAI/bge-small-zh Embedding（本地 CPU）
   ▼
ChromaDB PersistentClient 持久化（app/data/chroma/）
   │ 3. 自检：4 个测试 Query 验证召回
   ▼
构建完成（约 1 分钟，180MB 模型自动下载）
```

### 5.3 检索效果自检

构建脚本内置 4 个测试 Query（如"华法林与阿司匹林"），验证 Top-4 召回包含正确药品片段。实际集成测试中，"华法林+阿司匹林"组合能正确触发"严禁联用"级风险提示。

### 5.4 兜底设计

向量库未构建时（如首次部署未跑脚本），`rag.py` 自动降级为 DeepSeek 内置知识分析并在响应中标注 `source: "model_builtin"`，保证接口永不 500。

## 6. 工程化与质量保障

### 6.1 Git 规范

- Conventional Commits（feat/fix/docs/test/chore/ci），22 次细粒度提交完整记录 6 个阶段演进；
- 每个功能模块对应 1~2 次提交，与 AI 对话快照中的功能迭代一一对应；
- 打 `v0.3.0` 版本 tag 封档。

### 6.2 测试

- `backend/tests/test_api.py`：7 个 pytest 用例（健康检查、OpenAPI 路由存在性、422 参数校验、Pydantic 模型序列化、service 模块可导入），chromadb 缺失时自动 skip；
- `scripts/test_models.py`：真实模型连通性测试（vl/llm/tts 三模式）。

### 6.3 CI

GitHub Actions 双工作流：Python 3.11/3.12 matrix 跑 pytest；前端 npm build 并上传 dist 产物。

### 6.4 安全

- 全部 Key 走 `.env`（已 gitignore），仓库只含 `.env.example` 占位；
- CORS 通过 `FRONTEND_URL` 环境变量白名单收紧（验证：预检请求返回指定 origin 而非 `*`）；
- 图片上传限制 5MB；医疗建议全部附带就医提示与免责声明。

## 7. 可复现性论证

### 7.1 复现路径（实测约 10 分钟）

```
① git clone 仓库                    （1 分钟）
② python scripts/bootstrap.py       （一键：建 venv + 装前后端依赖 + 复制 .env）
③ 编辑 backend/.env 填入 2 个 Key    （2 分钟，Key 申请页见 README）
④ python scripts/build_vector_db.py （2 分钟，含模型自动下载）
⑤ 后端 uvicorn 启动 + 前端 npm run dev（2 分钟）
⑥ 浏览器访问 5173 / 8000/docs        （即刻验证）
```

### 7.2 环境一致性保障

- `requirements.txt` 锁定小版本号（如 `fastapi==0.115.0`）；
- 后端提供 Dockerfile（python:3.12-slim 基底），`start.sh` 首次启动自动构建向量库；
- 前端 `package-lock.json` 入库；`.env.example` 完整罗列全部环境变量及注释；
- `render.yaml` / `vercel.json` / `railway.json` 一键部署配置入库。

### 7.3 无 Key 也能跑

- Edge-TTS 与语音提醒功能完全免费无 Key；
- 前端 5 页面 UI、路由、本地存储在无 Key 状态下完整可演示；
- pytest 全绿（mock 环境）。

## 8. AI 协同开发过程复盘

本项目采用"人定意图、AI 实现、人验收"的协同模式，全过程 Prompt 链快照见 `docs/ai-prompts/`。以下三个片段对应三次典型的意图控制实践（完整链见快照文档）：

**片段一：让 VL 识图输出稳定 JSON**
初版提示词返回带 markdown 围栏的文本，解析频繁失败。通过追加"不要任何多余文字、不要 markdown 代码块"并让 AI 补充剥离围栏的容错解析函数，失败率降为 0。

**片段二：RAG 提示词的"抗噪"设计**
向量检索偶有无关片段混入，导致模型被噪声带偏。在提示词中显式声明"若片段与问题无关，请忽略片段"后问题消除。

**片段三：修复异步 TTS 超时**
Edge-TTS 在首次调用时偶发超时。通过引导 AI 定位到未复用 TCP 连接的问题，改为全局复用 `Communicator` 并加入重试，超时率显著下降。
